Design System

Foundations and components behind the AI-assisted shopping and checkout experience. Everything on this page is live and tokenised in three tiers — core, semantic, component: colours are chained CSS custom properties, type renders in the real faces, and the components respond to interaction. The same system exists in Figma as variables, text styles and variant components.

00

Token Architecture

Three tiers, strictly one-directional. Core tokens are raw values with no opinion; semantic tokens give them meaning; component tokens assign that meaning to parts. Components never reference a core value or a hex — every colour, space and radius on this page resolves through the chain. Inspect this page's CSS: the tiers are real custom properties.

1 · CORE
Raw material — no meaning

neutral/100 · orange/500 · gold/200 · dimension/16
Pure scales of colour and dimension. Nothing consumes them except Tier 2.

2 · SEMANTIC
Meaning — what it's for

text/primary → neutral/100 · action/primary → orange/500 · space/400 → dimension/16
UI concepts, not hexes. Rename a concept once and the whole product follows.

3 · COMPONENT
Assignment — where it lives

button/primary/background → action/primary · chip/radius → radius/pill
The only tier components are allowed to touch.

Resolution chain

01

Colour

One dark, editorial palette. Ink surfaces keep product photography dominant; a single terracotta accent is reserved for actions and price; warm gold tones are the AI assistant's voice — so intelligence is always visually distinct from the interface itself.

02

Typography

Two voices. Playfair Display carries the editorial, luxury register — titles, brand names, hero moments. Inter does the functional work — body, labels, prices, actions. Sizes are deliberately compact for a dense retail UI.

03

Spacing

A 4-point grid with 2-point half-steps below 16 for dense commerce components. Semantic names are numeric (space/100 = 4) so the scale can grow without renaming. Component padding uses 150–400; screen gutters are 500; section rhythm is 600–1000.

04

Radius

Soft but disciplined. Small radii keep commerce components crisp; large radii are reserved for conversational and device-level surfaces.

05

Components

Live HTML implementations of the system's components — try them. Each maps 1:1 to a Figma component with named variant properties.

Button

Padding 15 / 12 · radius-s · CTA type style. Properties: Type = Primary | Ghost · State = Default | Pressed. Primary fills color-accent, accent-deep when pressed. One Primary per view.

Press and hold to see the Pressed state.

Chip

Padding 7 / 13 · radius-pill. Property: Selected = False | True. Selection inverts to text-primary on ink — high contrast without touching the accent, so chips never compete with CTAs.

Click to toggle selection.

Assistant Pill

Padding 6 / 12 · radius 14. Property: Emphasis = Filled | Outline. Lives only inside Assistant Cards; Filled marks the recommended action (max one per card). Outline uses the gold AI voice, never UI grey.

Chat Bubble

Padding 11 / 14 · radius-l with a 3 px anchor corner toward the sender · Body type. Property: Sender = Assistant | Customer. Assistant sits on surface; Customer on accent.
